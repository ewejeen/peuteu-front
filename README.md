## API 콜 함수 호출 방식을 async await로 변경
### 변경 이유
- 기존에 async await 사용 없이 API 함수를 호출하다 보니 함수의 호출 순서 제어가 어려웠다.
- 하나의 함수에서 401 에러가 발생하면 다음 함수에서는 API 콜이 이루어지지 않기를 기대했는데 다음 함수들도 모두 마저 호출되었다.
- 따라서 순차적으로 함수 호출을 하기 위해 async await 방식을 도입했다.

### async await의 장점
- 가독성: 비동기 코드가 동기 코드처럼 보이게 되어 이해하기 쉬워진다.
    - await가 코드의 실행을 동기적으로 기다려주기 때문에, 코드가 흐름에 따라 자연스럽게 읽히고 이해하기 쉬워진다.
- 에러 처리: try-catch로 비동기 코드의 에러를 간단히 처리할 수 있다.
    - async 함수는 항상 Promise를 반환한다. 그래서 await는 그 Promise의 결과를 기다리게 만든다. 결과적으로, 비동기 함수의 반환값을 동기적으로 받아올 수 있다.
- Promise 체인 제거: then()과 catch() 체인 대신, 직관적인 흐름으로 코드 작성이 가능해진다.
- 비동기 함수의 순차 실행 제어: await로 비동기 작업을 순차적으로 처리할 수 있다.

** async/await를 사용하면 코드가 훨씬 간결하고, 관리하기 쉬우며, 비동기 작업의 복잡도를 크게 낮출 수 있다.
